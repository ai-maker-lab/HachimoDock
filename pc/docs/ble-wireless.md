# ESP32-P4 蓝牙连接

Waveshare ESP32-P4-WIFI6 v3 使用板载 C6 与 macOS 客户端连接。板子可用 USB-C 充电器供电，Mac 继续使用自己的网络。两端都需要支持 BLE 的版本。仓库内置的上游升级镜像仍对应上游发布版本。

## 首次连接和换电脑

1. 打开 Mac 客户端并允许访问蓝牙。给板子上电，同时按住外接面板 SW1 和 SW3 五秒，打开 30 秒的配对窗口。
2. 核对屏幕与 macOS 配对框里的六位数，在板上短按 SW1 确认并在 Mac 确认。短按 SW3 可拒绝。
3. 以后使用同一台 Mac 会自动重连。更换电脑时，在新 Mac 打开客户端，重复以上操作。新绑定成功后板子会删除旧绑定。
4. 要清空绑定，在配对窗口内、还没有出现比对数字时，按住 SW3 三秒。如果 Mac 仍记着已经清除的绑定，在系统蓝牙设置里忽略设备后重新配对。

## 功能范围

| 功能 | 蓝牙连接 |
| --- | --- |
| Agent 状态、会话卡片、按键事件 | 支持。Codex 和 Devin 等待用户操作时，板上静音弹窗显示会话和事项，约 8 秒后收起。选择和审批在电脑上完成 |
| 股票、天气和电脑状态 | Mac 获取数据，通过原有 `widget/data` 推送给板子 |
| 组件安装、更新、资源修复、删除 | 使用与 USB 相同的事务和回执。固件须声明 `widgetChunkAllPaths`；USB 在线时优先走 USB |
| 按键配置读取和上传 | 支持。Mac 收到板端写入回执后显示同步成功 |
| 板子截图 | 在设备页点击「截取板子画面」。按块读取同一帧，校验后显示 320 × 240 PNG |
| 完整形象包 | 固件声明 `bleAppearanceChunks` 时，可复用设备缓存或按块上传。上传新包会替换自定义槽中的旧形象。内置形象保留在 0 号槽 |
| 板载麦克风、语音对话、音频流、单独更新形象音效、固件升级 | 使用 USB 数据线 |

在 Mac 的「Agent 与形象」中可以同时查看各 Agent 最近上报的状态和时间。「已跟随」决定小狗的会话卡片和输入目标。板上打开「电脑状态」，向右翻过 CPU、内存等五项指标，即可查看同一份 Agent 状态。每个 Agent 展示最近一次上报；超过十分钟没有新记录就不再展示该状态。

桌面端通过 CoreBluetooth 连接。P4 运行 NimBLE，经 SDIO 调用 C6，无需更换 C6 固件。控制和组件消息沿用 JSON Lines，组件分块进入上游的暂存与提交逻辑。组件事务期间暂停数据快照，断线后重新发起事务。

## 构建与分区

在 `firmware/` 运行 `pio run -e esp32_p4_evboard_v3` 可构建 WiFi6 v3 蓝牙固件。其他有线目标沿用上游依赖和配置。IDF Component Manager 按锁文件下载官方 ESP-Hosted 1.4.7。构建时只调整两处错误处理：SDIO 读任务初始化失败时退出任务，传输重试耗尽时向 BLE 启动任务返回错误。小狗和 USB 在独立任务继续运行。重试次数和间隔沿用官方实现。见[构建期修改](../../firmware/ble/ble_host/hosted-startup.cmake)。

发布和完整初始化统一使用 [上游分区表](../../firmware/partitions.csv)。两个应用槽各 3 MiB，组件区 8.875 MiB，两个动画区各 8.5 MiB。已有相同布局的设备可直接按常规应用 OTA 更新。使用早期实验布局的设备要改成上游布局，须先备份有用数据，再通过 USB 完整初始化，并按新布局恢复可导出的组件和资源。整片烧录会覆盖设置、蓝牙绑定和已安装内容；应用 OTA 本身保留设备原有分区表。
