# PetUI Mirui 3D 渲染接口

适用于链接 Mirui 原生渲染器的 ESP32-P4 固件和同源 WAMR 检查器。组件把玩法写在 WASM 里，每次绘制提交相机、地形或模型，宿主生成 RGB565 画面。碰撞、关卡生成、航线、图鉴、存档与成就由组件或相应宿主接口实现。

## 选择接口

在 `hachi_init()` 调用 `hachi_canvas640()`，在 `hachi_frame()` 提交下面的绘制请求。组件导入模块均为 `hachi`，四个函数的 WASM 签名均为 `(i32) -> i32`，参数是请求结构在模块线性内存中的 32 位偏移。C/C++ 声明与布局见 [SDK](../sdk/hachi.h)。

| WASM 导入 | C/C++ 入口和请求 | `runtime/widget.json` 字段 | USB hello 能力字段 | 两边共同的值 |
| --- | --- | --- | --- | --- |
| `hachi.stack_draw` | `hachi_stack_draw(const hachi_stack_scene_t *)`，48 字节 | `hachiStack` | `widgetWasmSpriteStack` | `mirui-sprite-stack-v1` |
| `hachi.terrain_draw` | `hachi_terrain_draw(const hachi_terrain_scene_t *)`，56 字节 | `hachiTerrain` | `widgetWasmStackTerrain` | `mirui-height-field-v1` |
| `hachi.world_draw` | `hachi_world_draw(const hachi_world_scene_t *)`，64 字节 | `hachiWorld` | `widgetWasmStackWorld` | `mirui-world-canvas-v1` |
| `hachi.scene_draw` | `hachi_scene_draw(const hachi_scene_t *)`，124 字节 | `hachiScene` | `widgetWasmScene` | `mirui-scene-v1` |

| 场景 | 行为 |
| --- | --- |
| 单独叠加 3D 模型 | `stack_draw` 将透明背景的 3D 模型绘制到自定义窗口。模型互相遮挡，窗口之外保留已有画面。 |
| 先绘地形，再叠模型 | `terrain_draw` 使用 320×240 高度场视口，2×放大到全屏。可在同帧之后调用一次 `stack_draw`，两个通道各有深度缓冲。 |
| 模型能被地形遮挡 | `world_draw` 将高度场与最多 4 个模型投影到同一深度缓冲。默认 320×240 再 2×放大。 |
| 迷宫、地表或太空加一批对象 | `scene_draw` 在 160×120 场景共享深度，4×放大覆盖 640×480。模式 0 高度场，模式 1 贴图墙网格，模式 2 空场景。 |

`world_draw` 和 `scene_draw` 各自独占该帧 3D 提交。座舱、按钮和 HUD 用普通画布 API 在场景后画，文字由宿主合成。按请求结构内的顺序提交资源，并保持每个偏移和相应字节范围在同步调用结束前有效。返回值 `0` 表示成功，`-1` 表示参数、资源或配额校验失败，`-2` 表示画布或回调位置不符，或本帧的 3D 提交已经占用，`-3` 表示无法创建渲染工作区。WAMR 还会拦截非法线性内存访问。调用失败后在下一帧提交修正的请求。

### 打包、兼容和验收

- 保留 `widgetWasm=hachi-wasm-v1` 和 `widgetWasmCanvas=640x480-v1` 的基础能力检查。工具链从 WASM 导入生成四种渲染声明，设备安装时再次校验。签名、资源和回放由链接同一渲染器的 `petui-wasm-check` 校验。连接时以实际 USB hello 为准。旧版 Pet Manager 需要更新到包含该 ABI 的作者工具，才能校验和同步这些包。
- PetUI 的源码快捷构建入口接受 C。C++ 通过 Clang 的 freestanding `wasm32-unknown-unknown` 目标自行构建，选择 `-mcpu=mvp`，使用相同的导入、固定内存和四项导出 `memory`、`hachi_init`、`hachi_event`、`hachi_frame`。导出的成品 `runtime/app.wasm` 走同一套打包与回放。C++ 项目需要自行链接所用的运行库，包括编译器可能生成的 `memcpy` 等调用，并满足导入白名单。
- `world_draw` 可加空 WASM 自定义节 `mirui-world-canvas-160-v1`。设备若报告 `widgetWasmStackWorld160=mirui-world-canvas-160-v1`，该模块使用 160×120 再 4×放大。其余兼容的 world 宿主保留 320×240。相机惯例与 HUD 坐标保持一致。该节是渲染偏好，因此无需额外的清单字段。
- 原生画布模块也可声明空自定义节 `hachi-frame-continuation-v1`。设备若报告 `widgetWasmFrameContinuation=hachi-frame-continuation-v1`，`hachi_frame` 的参数置位 `HACHI_FRAME_CONTINUATION_FLAG`。清除此位得到耗时。宿主保留最近完整帧，期间允许无绘制回调分批推进；真正提交时仍从黑底绘制完整一帧。每次回调独立受 160,000 指令预算约束。连续最多 8 次短让步，随后按普通间隔让步。完成帧按配置的显示间隔扣减渲染用时。
- 回放覆盖真实按键、场景切换、遮挡和 HUD。真机同时看 `wasmFramesPublished`、`wasmFrameContinuations` 与 LCD 的 `renderSubmittedFrames`。前两者是 WASM 侧的发布与续帧计数。场景的 `wasmWorldTerrainUs`、`wasmWorldModelsUs`、`wasmWorldResolveUs` 分别记录最近一次构建世界背景、绘制切片及模型、解析旋转与 RGB565 展开耗时。帧率依据两个采样时刻的差值计算。
- 三维工作区是按需分配并跨帧复用的原生内存。屏幕仍是 640×480，选择 160×120 时模型与地形分辨率随之减少，640×480 文字层有独立的分辨率与预算。

## 通用相机与资源布局

多字节字段都是小端序。Q8 的 256 表示 1，Q12 的 4096 表示 1，Q16 的 65536 表示 1。模型坐标从局部坐标变换到相机空间，轴顺序为右、前（深度）、上。宿主应用相机坡度，并对含滚转字段的请求处理滚转。

| 项 | `stack_draw` | `terrain_draw`、`world_draw`、`scene_draw` |
| --- | --- | --- |
| 相机比例 Q8 | 64–2048 | 128–4096 |
| 透视 Q16 | 0–8192，0 为正交 | 0–8192，墙网格模式 512–8192 |
| 坡度 Q8 | −512–512 | −512–512 |
| 中心（转换为 Q8 前） | 窗内相对坐标，X −160–320、Y −120–240 | 以 320×240 表示，X −320–640、Y −240–480 |
| 相机位置 | 模型使用相机空间 | 高度场与墙网格 X/Y 为 `[0, 1024)` 世界单位，太空支持 ±2,097,152，海拔 0–512。偏航和滚转正弦/余弦为 Q12。 |

- `stack_draw` 视口最大 160×120，缩放为 1–4 的整数倍，输出裁剪到 640×480。
- `hachi_stack_instance_t` 为 60 字节。模型原点各轴在 ±1024 世界单位内，轴矩阵元素为 −256–256 的 Q8，模型每格大小以 `scale_q8` 的 1–1024 给出。最多 4 个实例（单独 stack 必须至少 1 个），scene 可到 16 个。每模型最多 4096 个不透明样本，每次提交合计最多 8192 个。
- 高度场资源共 9216 字节。4096 个高度值（0–63）、4096 个材质索引（0–16）、1024 个云密度（低四位）。地表为 64×64、每格 16 世界单位，并循环取样。云为 32×32 循环网格。调色域包含 17 个 RGB888 项。相机原点是采样投影面的世界位置；从眼睛位置构造时沿视线向前移一个投影距离，使模型与地形投影一致。
- 本仓库的场景模式 0 按相邻高度和世界坐标纹理调整地表明暗，同时保留材质色和距离雾。兼容的单独高度场与 world 通道继续使用各自的高度场调色。

## 场景专用字段

| `hachi_scene_t` 字段 | 用途和限制 |
| --- | --- |
| `terrain` | 56 字节高度场及相机结构。仅模式 0 使用其中的资源偏移。 |
| `map`、`map_width`、`map_height` | 墙网格至多 32×32 个字节，单元边长 16。0 为空格，非零为从 1 开始的墙贴图编号。每屏幕列最多沿射线遍历 64 次网格交点。太空中 `map` 是星场种子。 |
| `art`、`art_count`、`palette` | 至多 32 张连续 16×16 的索引贴图，每像素取低四位。共用 16 项 RGBA8888 调色板。面向镜头的贴图用索引 0 表示透明。 |
| `billboards`、`billboard_count` | 至多 48 项。每项 24 字节，含右/前/上的 Q8 原点、Q8 正宽高（各 1–16384）和从 0 开始的贴图编号。整帧裁剪后的绘制面积预算为 38,400 像素。先提交重要对象。普通场景原点各轴 ±1024，太空且透视 ≥512 时各轴 ±2,097,152。 |
| `instances`、`count` | 至多 16 个 SSK1 模型，合计 8192 个不透明样本。模型与地形、墙和 cutout 共用深度。 |
| `sky_rgb`、`ground_rgb`、`fog_rgb` | `0xRRGGBB`。墙模式中 sky 与 ground 为天花板和地面底色。 |
| `fog_start_q8`、`fog_end_q8` | 0–1024 世界单位，结束距离须 ≥ 开始距离。由表面色过渡到雾色。太空模式两个值都设为 1024 时关闭距离雾。 |
| `flags` | 位 0 启用程序星点。太空中根据星区坐标和种子投影出近、中、远三层 3D 星点。 |

墙模式的玩家眼睛是射线原点，地面为零高、天花板为 16 世界单位。提交处于墙模式的模型或 cutout 时，沿相机前向减去投影距离 `65536 / perspective_q16`。世界空间的地面砖缝与微纹理随相机透视移动。太空深度排序覆盖可见的行星贴图与星点，行星航程和接近地表的状态转换由游戏控制。早期试验固件曾使用同一 scene 声明，本参考的扩展太空范围以包含当前渲染器的构建为准。

## SSK1 模型格式

将 MIRX 的 Sprite Stack 基础图集使用 `mirui-pack-stack input.mirx output.ssk [pivot_z_q8]` 转为 SSK1，也可自行生成。只允许完全不透明和完全透明的源像素，透明像素不写入 SSK1。

| 顺序 | 类型 | 内容 |
| --- | --- | --- |
| 1 | 4 字节 | `SSK1` |
| 2 | 4 × u8 | 宽高 1–64，层数 1–16，调色板长度 1–128 |
| 3 | 3 × i16 | X/Y/Z 轴枢轴，Q8，各 ±16384 |
| 4 | u16 | 层间距，Q8，1–1024 |
| 5 | (层数 + 1) × u16 | 从下到上的样本边界，起点 0，终点为样本数 |
| 6 | 调色板长度 × 4 字节 | RGBA8888，被引用的颜色 alpha 为 255 |
| 7 | 样本数 × 3 字节 | 每个样本的 x、y、从 0 开始的颜色索引。样本数 1–4096。 |

正交投影下，最后一个调色板条目为字节 `56 4F 58 00` 时，支持该扩展的宿主会为模型绘制连接起来的体素外表面，共用场景深度缓冲。该条目留给宿主识别，样本索引不能指向它。体素的高度为层间距，体素中心的坐标沿用原格式。每次提交至多检查 196,608 个裁剪后的投影面包围盒像素，原有样本配额仍适用。旧宿主和透视视图可读取同一资产并以薄片方式绘制。
