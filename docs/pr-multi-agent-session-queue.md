# 统一多 Agent 会话队列，按所选会话路由状态与语音

## 设计理念

用户在设备上要做的决定是「接下来关注哪段对话」。因此，启用 Agent 只决定哪些来源可以提供卡片，所有来源的卡片进入同一个队列，用户只需选一次会话。如果还要求单独选择当前 Agent，一次跨来源切换就需要同时更新两个选择，屏幕上显示的对话和语音实际进入的对话可能错开。

每张卡片保留原始 `sessionId` 和来源 `agentId`。例如从 Codex 会话切到 Claude 会话后，设备显示 Claude 的来源标签，桌面端从选中卡片取得这两个字段，找到对应的 Agent 和对话来处理状态与语音。卡片的排序和过期由桌面端统一处理，这样各来源可以采用不同的数据获取方式，同时遵循同一套展示规则。

宠物形象属于整台设备，用户只需配置一次，跨 Agent 切换会话时沿用同一形象。USB 和 Wi-Fi 也共用这套会话选择规则，连接方式和固件能力决定队列与选择事件如何传递。

## 实现与兼容性

- 桌面端统一管理卡片的排序、保留和过期。移出某个 Agent 时，桌面端从队列中移除该来源的卡片。非当前 Agent 通过定期获取会话快照参与聚合。
- 固件按每张卡片携带的 `agentId` 和原始 `sessionId` 识别会话，处理按键切换和完成提示。USB 和 Wi-Fi 语音链路在收到设备上报的目标时，会与桌面端绑定的目标做校验。
- USB 支持下发合并队列。Wi-Fi 根据设备上报的会话选择能力决定下发范围：支持该能力时下发合并队列，旧固件继续接收当前来源的会话。当前 README 仍将所有 Wi-Fi 连接描述为单来源，与实现有出入。

合并前值得重点验证三个场景：

- Windows 上，Codex 无法唯一定位所选会话时，语音仍可能进入前台输入框。
- Wi-Fi 设备刚切换卡片就按住说话时，桌面端目标可能尚未同步，导致这次按住被丢弃。重连时也需确认设备选中的卡片能正确恢复。
- 切换当前 Agent 后，如果首次完整快照拉取失败，检查临时缓存是否导致仍活跃的卡片提前过期。
